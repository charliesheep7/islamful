4. Enable Google in Supabase Auth providers with the correct Google OAuth client ID and secret. In Google Cloud, register `https://xyccxfjiiilxfsafglbw.supabase.co/auth/v1/callback` as the authorized redirect URI. Keep the secret only in Supabase, never in the website's public environment variables.
5. Verify real signup → email confirmation, password login, recovery → password update, Google redirect → return to original English/Arabic page, session refresh and sign-out on the actual deployment.

Auth follows the Supabase [SSR client guide](https://supabase.com/docs/guides/auth/server-side/creating-a-client). Middleware refreshes existing cookie sessions and preserves locale headers. Server-side protected features must verify identity with `getUser()` or `getClaims()` before returning private data; client UI state is not authorization. Callback destinations are restricted to local non-auth paths. Auth routes are noindex and callback responses are no-store.
